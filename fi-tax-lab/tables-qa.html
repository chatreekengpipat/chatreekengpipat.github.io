  • ACDOCA = Universal Journal (S/4 line-item เดียวรวม FI+CO+ML) = แหล่งจริงของ PC · RI · segment · VAT code — อ่านด้วย RLDNR='0L' + KTOSL
  • KTOSL (transaction key) แยกบรรทัด: WIT=WHT · VST=input VAT · XST=PC/RI ฝั่ง invoice · MWS=output VAT
  • BSEG = classic FI line items ยังอยู่ — ใช้บาง field เช่น clearing doc (AUGBL) บน WIT line (RPT-1 field 4)
  • BSAK = สะพานเชื่อม payment↔invoice ผ่าน AUGBL (clearing) — แกน join ของ RPT-1
  • BSET = tax segment (base/amount ภาษี) · BKPF = doc header (currency/rate/date)
  • WITH_ITEM = WHT amounts; suffix HB=doc · HH=LC1 · H2=LC2 (หัวใจของ FRM-2)
  • rate: WHT rate = T059Z-QSATZ · exchange = TCURR-UKURS · rate type per country = T005-KURST
  • validate master: PC↔CEPC · RI↔T8JJ · BP tax no↔DFKKBPTAXNUM
  • delta discipline: รู้ชัดว่าอะไร “Same as ECC” และอะไรคือ retrofit (GL renumber · doc type · +PC/RI · source-table shift → ACDOCA) — ตารางเทียบอยู่ในหน้าของแต่ละ object

ACDOCA vs BSEG — คำถามยอดฮิต

ถ้าตอบอันนี้ได้คม = ดูโปรเหนือคนอื่นทันที

ACDOCA (Universal Journal) คือหัวใจของ S/4HANA — รวม FI + CO + Material Ledger + asset ไว้ใน line-item table เดียว เป็น source of truth สำหรับ reporting และ analytic dimensions (Profit Center, Recovery Indicator, Segment, VAT code). BSEG (classic FI line items) ยัง generate อยู่เพื่อ compatibility แต่ report ยุค S/4 อ่าน ACDOCA เป็นหลัก

อ่าน ACDOCA ยังไง — RLDNR + KTOSL

ทุกครั้งที่ดึงจาก ACDOCA จะ fix RLDNR='0L' (leading ledger) แล้วกรอง KTOSL (transaction key) เพื่อเลือก “บรรทัดที่ต้องการ”:

KTOSL='WIT'
Withholding — บรรทัด WHT · ดึง PC/RI ฝั่งจ่าย
KTOSL='VST'
Input VAT — ดึง VAT code (MWSKZ)
KTOSL='XST'
Invoice side — ดึง PC/RI ฝั่ง invoice
KTOSL='MWS'
Output VAT — ฝั่งขาย

แล้วทำไมบาง field ใช้ BSEG?

RPT-1 field “Doc WHT FX Adj” FD ระบุอ่าน BSEG (BELNR/GJAHR/BUKRS ของเอกสารจ่าย, KTOSL='WIT') เพื่อดึง AUGBL (clearing document) ของบรรทัด WHT — เป็นการหยิบ line-level clearing linkage ที่ระบุไว้ที่ BSEG · ส่วน PC/RI/VAT code (field 17/18/32/33/34) หยิบจาก ACDOCA

ประเด็นตอบ: “S/4 อ่าน analytic dims (PC/RI/segment/MWSKZ) จาก ACDOCA · ส่วน BSEG ใช้เมื่อต้องการ line-level field เฉพาะ (เช่น clearing AUGBL ของ WIT line) — FD ของ RPT-1 mix ทั้งสองตัวโดยตั้งใจ”

Q&A Drill — “ถ้าเขาถามว่า…”

อ่านคำถาม → ตอบในใจ → กดเฉลย · ทำซ้ำจน reflex

Q1RPT-1 ดึง Profit Center / Recovery Indicator จากตารางไหน อย่างไร?
เฉลย
จาก ACDOCA (RLDNR='0L') กรอง KTOSL='WIT' สำหรับฝั่งจ่าย และ KTOSL='XST' สำหรับฝั่ง invoice → fetch PRCTR / RECID
Q2ทำไม field “Doc WHT FX Adj” ใช้ BSEG ไม่ใช่ ACDOCA?
เฉลย
FD ระบุอ่าน BSEG (BELNR/GJAHR/BUKRS ของเอกสารจ่าย, KTOSL='WIT') เพื่อดึง AUGBL (clearing document) ของบรรทัด WHT — เป็น line-level clearing linkage · ส่วน analytic dims (PC/RI/VAT code) หยิบจาก ACDOCA
Q3ACDOCA คืออะไร ต่างจาก BSEG อย่างไร?
เฉลย
ACDOCA = Universal Journal — line-item table เดียวของ S/4 รวม FI+CO+ML = source of truth สำหรับ reporting/analytic (PC/RI/segment/MWSKZ) · BSEG = classic FI line items ยัง generate อยู่ ใช้บาง field เฉพาะ
Q4RPT-1 เชื่อมเอกสารจ่าย → invoice ด้วยตารางอะไร?
เฉลย
BSAK — AUGBL (clearing) = เลขเอกสารจ่าย แล้วคืน BELNR ที่ BELNR ≠ AUGBL (+ BUKRS, GJAHR) = เลข invoice
Q5WHT rate ของ RPT-1 กับ FRM-2 มาจากที่เดียวกันไหม?
เฉลย
ไม่ — RPT-1 อ่าน T059Z-QSATZ (by LAND1=TH, WITHT, WT_WITHCD) · FRM-2 hardcode อัตรา DTA ตาม tax code (D1=8%…H4=10%) โดยอ่าน code จาก WITH_ITEM-WT_WITHCD
Q6RPT-2 ดึงข้อมูลภาษีหลักจากตารางไหน และ Tax ID คู่ค้าจากไหน?
เฉลย
ภาษีหลักจาก BSET (ฐาน RFUMSV00) + BKPF/BSEG · Tax ID คู่ค้าจาก LFA1/KNA1 → STCD3 (นิติบุคคล) / STCD1 (บุคคล)
Q7RPT-2 retrofit อะไรจาก ECC บ้าง (ตอบเร็ว 4 ข้อ)?
เฉลย
(1) GL renumber 21500020→A213X025 · (2) doc CC→JD/JK · (3) user exit EJVA017 (substitute tax code cash-call) retrofit เข้าโปรแกรม · (4) selection +PC(CEPC)/RI-further + output +Alt Ref +VIM scan date (/OPT/VIM_1HEAD) → 36 คอลัมน์
Q8RPT-2 แปลงเป็นสกุลอะไร ด้วย rate type ใด มาจากตารางไหน?
เฉลย
CoCd OM01: LC1 = OMR (3 ทศนิยม) · LC2 = USD · ไม่มี LC3 · exchange rate type ของรายงาน = ZOM (Oman avg daily) จาก T005-KURST → อัตราใน TCURR (ZOM vs mid ยังเปิด — G10 / C18)
Q9FRM-2 ตัดสินใจพิมพ์ MMK หรือ USD จาก field ไหน และยอดจาก field อะไร?
เฉลย
ตัดสินจาก BKPF-WAERS (=MMK → MMK, else USD) · ยอดจาก WITH_ITEM: MMK=QSSHH/QBSHH, USD=QSSH2/QBSH2, doc=QSSHB/QBSHB
Q10FRM-2 หา Tax ID ทั้ง 2 ฝ่าย และชื่อประเทศ vendor ยังไง?
เฉลย
Tax ID ผู้ถูกหัก = DFKKBPTAXNUM (PARTNER=WT_ACCO, TAXTYPE MM3/MM0 → TAXNUM/TAXNUMXL) · ผู้หัก = T001-STCEG · ประเทศ = BSAK→LIFNR→LFA1(LAND1)→T005T(LANDX)
Q11KTOSL แต่ละค่าใน ACDOCA หมายถึงอะไร?
เฉลย
WIT=withholding · VST=input VAT · XST=ใช้ดึง PC/RI ฝั่ง invoice · MWS=output VAT — fix RLDNR='0L' เสมอ
Q12document splitting / segment เกี่ยวกับ report พวกนี้ยังไง?
เฉลย
Segment = tax regime ถูก derive ด้วย substitution TAX-ENH-4 (GGB1): ZTAXB_T04 (G/L) → ZTAXB_T05 (CC + IO) → segment ของ profit center · document splitting แตกบรรทัด BS (vendor / tax / WHT) ตาม PC / segment ของบรรทัด P&L → ACDOCA จึงมี WIT line หลายบรรทัดต่อเอกสาร multi-PC (ต้นเรื่อง TKT-01) · segment ยังตัดสิน rate ของ LC3
Q13RPT-2 มีกี่ data path และ cash call มาจากตารางไหน?
เฉลย
สอง path: standard = BKPF → BSET · cash call = BKPF → BSEG บรรทัด vendor (I0 ไม่มีบรรทัดภาษี) · LC2 base = BSEG-DMBE2 · attribute JVA จาก ACDOCA แถวเดียวที่ match ด้วย key เต็ม (ACDOCA-DOCLN = BSEG-BUZEI)
Q14FRM-1 หา Tax ID ผู้ขายจากไหน และ defect alternative payee คืออะไร?
เฉลย
WITH_ITEM-WT_ACCO → DFKKBPTAXNUM (TAXTYPE TH1 บุคคล / TH3 บริษัท → TAXNUM/TAXNUMXL) · defect: เมื่อมี payee บนเอกสาร FRM-1 ยังพิมพ์ BP master แทน BSEC (certificate ZTAXA_F02 ใช้ STCD3 → STCD1 แล้ว)
Q15ENH-1 สร้างไฟล์ด้วยอะไร และต้องมีเอกสารอะไรก่อนเทสระดับ field?
เฉลย
DMEEX format trees ZWHTFILE_* + exits ZDMEE_EXIT_WHT_BASE/_AMT + enhancement ZTAXA_E01 (sum partner PND1A, sort) · ต้องมี DMEEX mapping workbook (positions, lengths, constants, วันที่ พ.ศ.)
