วัตถุประสงค์ + กฎแปลงค่าเงิน (Section 9)

รายงานเอา WHT (ฝั่ง PND54) มาเทียบกับ VAT36 (ฝั่ง invoice) — ต้องแปลง FC เป็น THB ตามมาตรา 9 ของประมวลรัษฎากร

เข้าใจง่าย ๆ: เวลาจ่ายค่าบริการให้ต่างชาติ มักเกิด 2 ภาระพร้อมกัน — หัก WHT (ยื่น PND54) และตั้ง VAT แทน (VAT36 → PP36) รายงานนี้ดึงทั้งสองฝั่งมาวางคู่กัน + แนบ Profit Center / Recovery Indicator เพื่อตรวจว่ายอดตรงกัน

3 กฎแปลงค่าเป็น THB

Rule 1
Invoice FC + Payment FC
invoice + จ่าย เป็นสกุลต่างประเทศ (USD/EUR/GBP) → ใช้ สกุลที่จ่าย (payment currency) แปลงเป็น THB
Rule 2
Invoice THB + Payment USD
invoice เป็น THB, จ่ายเป็น USD → ใช้ สกุล invoice (THB) → ไม่ต้องแปลง
Rule 3
Invoice FC + Payment THB
invoice เป็นสกุลต่างประเทศ, จ่ายเป็น THB → ใช้ สกุล invoice แปลงเป็น THB
สรุปกฎ: ถ้าจ่ายเป็นเงินตราต่างประเทศ ให้ยึด สกุลที่จ่าย · ถ้าจ่ายเป็น THB ให้ยึด สกุล invoice · ถ้า invoice เป็น THB อยู่แล้ว = ไม่แปลง

    Step 28 final (3-Sep-2026)

    • เลิก ratio approach → TCURR rate type M เท่านั้น · FCURR = สกุล invoice (BSAK-WAERS) → THB · GDATU = วัน posting ของ payment − 1 แบบ ≤ fallback · guard UKURS/FFACT = 0 · 5 ทศนิยม
    • VAT36 FC → THB สองขั้น (invoice ccy → USD → THB) เขียนเป็นการคูณ rate สองตัว — ใช้กับคอลัมน์ VAT36 เท่านั้น
    • แถว 5A ใช้ KURSF ของเอกสารตัวเอง (5A ที่ยังไม่จ่าย = provisional) · 5G ใช้ TCURR entry ที่สองก่อนวันจ่าย (T-2 วันทำการ) และการรวมใน R03 ยังรอคำตัดสิน
    • ผล: VAT36 base ≠ WT base บนแถวที่จ่าย FC — by design · sign: abs(FC) × sign(RC)
    • Steps 11/12 อ่าน WITH_ITEM ของ payment · steps 20/21 อ่าน WITH_ITEM ของ invoice ตาม FD — accepted 16-Sep (เปลี่ยน = CR)

    Multi-PC / multi-invoice

    • Split lines (TKT-01): 1 แถวต่อ ACDOCA WIT line (HSL ≠ 0) · WHT = HSL ของบรรทัด · base prorate ตาม WIT ratio บรรทัดสุดท้ายรับเศษ · payment หลาย vendor ไม่ split · VAT36 บนแถว split + partial payment ยังเปิด (D2)
    • Multi-invoice payment (14-Sep, defect เปิด): รายงาน resolve AP voucher ตัวเดียวแล้ว stamp ทุกแถว · การอ่าน FD ที่ตกลง: หนึ่งแถวต่อ invoice ที่ถูก clear ซึ่ง WITH_ITEM ของตัวเอง match vendor + WHT type + code ของแถว payment (loop ไม่ใช่ first hit) · แบ่ง WHT ตาม invoice (WT_QBSHB) หรือ prorate ตาม base — รอ team lead (D3)

    3 objects ของซีนั่งอยู่บน selection screen เดียวกัน (+ FRM-3 ของเพื่อนร่วมทีม)

    ทำไมส่วนนี้สำคัญ: ซีเป็นเจ้าของ ทั้ง RPT-1, FRM-1 และ ENH-1 ซึ่งใช้ wrapper / filter เดียวกัน — เวลาแก้ selection screen หรือ logic การกรอง ต้อง regression ทั้งสามตัว (และ FRM-3) และเวลารายงาน defect ต้องระบุให้ชัดว่าพังที่ ALV / ฟอร์ม / ไฟล์
    ตัวเรียกร่วมZTAXB_R01 → ZTAXA_R01 (Z-copy ของ RFIDYYWT / Generic Withholding Tax Reporting)

    9

    Self-check

    ตอบในใจก่อนกดเฉลย — โฟกัสจุดที่ออกสอบ/ทดสอบบ่อย

    1. TAX-RPT-1 ใช้โปรแกรมอะไร และเพิ่ม field อะไรในจอเลือก?

    ดูเฉลย
    T-code ZTAXB_R01 → ZTAXA_R01 (Z-copy ของ RFIDYYWT / S_P00_07000134 ตามที่ FD อ้าง) · เพิ่ม Profit Center (validate กับ CEPC) และ Recovery Indicator (จาก T8JJ) ใต้ Further Selections

    2. Invoice เป็น USD จ่ายเป็น THB — ใช้สกุลไหนแปลงเป็น THB?

    ดูเฉลย
    ใช้ สกุล invoice (USD) แปลงเป็น THB (Rule 3 / TC-004)

    3. ฝั่ง VAT36 (invoice) ใช้ rate ของวันไหน และจากตารางใด?

    ดูเฉลย
    Posting date T-1 (วันทำการก่อนหน้า) · จาก TCURR-UKURS ที่ GDATU = BUDAT − 1

    4. ต้องรันโปรแกรมใดก่อน recon จึงจะได้ column WHT FX Adj และ VAT36 Doc No.?

    ดูเฉลย
    ZTAXA_R03 (WHT adj → Doc WHT FX Adj) และ ZTAXA_R02 (VAT36 → VAT36 Doc No.)

    5. เชื่อมเอกสารจ่ายไป invoice ผ่านตารางอะไร?

    ดูเฉลย
    BSAK — AUGBL (clearing) = เลขเอกสารจ่าย แล้วคืน BELNR (invoice) ที่ BELNR ≠ AUGBL
