SE16N — ดึงข้อมูลใน SAP แบบครบถ้วน

T-code · SE16N ชื่อเต็ม · General Table Display ญาติ · SE16 · SE11 · SE16H · SQVI ใช้กับ · ทุก object ในเล่มนี้

SE16N คือ “ประตูหลัง” เข้าไปดูข้อมูลดิบในตารางของ SAP โดยไม่ต้องผ่านหน้าจอ transaction สำหรับ consultant สายภาษี มันคือเครื่องมือที่ใช้ บ่อยที่สุด — ใช้พิสูจน์ว่า “รายงานผิด” หรือ “ข้อมูลผิด” · ใช้เตรียมข้อมูลทดสอบ · ใช้ตอบคำถาม user ภายใน 2 นาที คนที่ใช้ SE16N เป็น จะ debug ได้เร็วกว่าคนที่ไม่เป็น 5–10 เท่า

Key Takeaways — 8 ข้อที่ต้องติดตัว
  • ล้าง “Maximum no. of hits” ทุกครั้ง — default 500 ทำให้คุณสรุปผิดโดยไม่รู้ตัว
  • ปุ่ม “Number of Entries” นับจำนวนแถวโดยไม่ต้องดึงข้อมูล = เร็วและปลอดภัย
  • ไอคอนลูกศร (→) ท้ายช่อง = multiple selection · ใส่ได้ทั้ง include / exclude / range / pattern
  • เครื่องหมาย * = อักขระกี่ตัวก็ได้ · + = อักขระ 1 ตัว
  • Settings → Fields เพื่อลดคอลัมน์ = เร็วขึ้นมากกับตารางใหญ่อย่าง ACDOCA
  • ตารางใหญ่ต้องมี filter บน key field เสมอ — ACDOCA ไม่มี BUKRS+GJAHR = รอเป็นชาติ
  • SE16N ใน production = read-only เท่านั้น · &SAP_EDIT ถูกล็อกและถูก audit
  • ถ้าต้อง join ข้ามตาราง → SE16N ทำไม่ได้ · ใช้ SQVI หรือขอ CDS view
1

SE16N คืออะไร และทำไมสายภาษีต้องใช้

SAP เก็บทุกอย่างในตารางฐานข้อมูล — เอกสารบัญชี · master data · config · ตาราง custom หน้าจอ transaction ปกติ (เช่น FB03, S_P00_07000134) เป็นเพียง “มุมมองที่จัดไว้ให้” SE16N คือการเปิดดู ข้อมูลดิบตรง ๆ

3 สถานการณ์ที่ SE16N คือคำตอบเดียว

  1. “รายงานไม่แสดงรายการนี้” — ต้องพิสูจน์ว่าข้อมูลมีอยู่จริงในตารางไหม ถ้ามี = โปรแกรมกรองผิด · ถ้าไม่มี = ข้อมูลไม่ถูกบันทึก
  2. “ต้องเตรียมข้อมูลทดสอบ” — หาเอกสารที่มีเงื่อนไขครบ (เช่น WHT type 3A + profit center X + ledger 0L) ก่อนรันรายงาน
  3. “config ตั้งไว้ว่าอะไร” — ตาราง custom (ZTAXA_T01, ZTAXB_T02) ดูผ่าน SE16N ได้ทันทีโดยไม่ต้องรอ dev

เขียนเงื่อนไข — ครบทุกแบบ

นี่คือทักษะที่แยก “คนใช้ SE16N ได้” ออกจาก “คนใช้ SE16N เป็น”

4.1 · แบบพื้นฐาน (กรอกในช่องหน้าจอตรง ๆ)

ต้องการวิธีกรอกตัวอย่าง
ค่าเดียวใส่ช่องซ้ายอย่างเดียวTH01
ช่วงใส่ทั้งช่องซ้ายและขวาTH01 ถึง 1010
ขึ้นต้นด้วย…ใช้ * ท้ายA21* → A2100000, A2199999 …
ลงท้ายด้วย…ใช้ * หน้า*999999999
มีคำนี้อยู่ตรงกลางครอบด้วย **ROYAL*
อักขระเดียวใช้ +3+ → 3A, 3B, 3C … (ไม่ติด 3AB)
จำ 2 ตัวนี้ให้แม่น: * = อักขระกี่ตัวก็ได้ (รวม 0 ตัว) · + = อักขระ 1 ตัวพอดี → ถ้าอยากได้ WHT type ที่ขึ้นต้นด้วย 3 และยาว 2 ตัว ให้ใช้ 3+ ไม่ใช่ 3* (3* จะติด 3 เดี่ยว ๆ ด้วย)

4.2 · Multiple selection (ไอคอนลูกศร →) — 4 แท็บ

คลิกไอคอนลูกศรท้ายช่อง จะได้หน้าต่างที่มี 4 แท็บ:

แท็บชื่อใช้ทำอะไร
1 (เขียว)Select Single Valuesใส่ค่าหลายค่าทีละบรรทัด เช่น 3A 3B 3C 3D 3E 3F
2 (เขียว)Select Rangesใส่หลายช่วงพร้อมกัน
3 (แดง)Exclude Single Valuesไม่เอาค่าเหล่านี้
4 (แดง)Exclude Rangesไม่เอาช่วงเหล่านี้

ในหน้าต่างนี้ยังมีปุ่ม “Upload from clipboard” (วางค่าจาก Excel ทีเดียวหลายร้อยบรรทัด) และ “Import from text file” — ประหยัดเวลามหาศาลเวลาต้องเช็คเอกสารเป็นร้อยใบ

4.3 · Selection options (ตัวดำเนินการเปรียบเทียบ)

4.4 · การหาค่าว่าง / ไม่ว่าง

หา “ค่าว่าง” ปล่อยช่องว่างไว้เฉย ๆ → ไม่ได้ผล! (แปลว่า “ไม่กรอง field นี้”) วิธีที่ถูก: ใช้ Selection options → Equal to แล้วปล่อยค่าเป็นช่องว่าง หรือใส่เครื่องหมาย = ตามด้วยว่าง หา “ไม่ว่าง” (เช่น WT_WITHCD ต้องไม่ว่าง ตามที่ TAX-FRM-1 กำหนด) ใช้ Selection options → Not equal to แล้วปล่อยค่าเป็นช่องว่าง หรือใช้ Greater than + ค่าว่าง
เคล็ดลับที่ใช้ได้ทุกวัน: ถ้าไม่แน่ใจว่าเงื่อนไขถูกไหม ให้กรองหลวม ๆ ก่อนแล้วใช้ ปุ่มกรวย (Set filter) บน ALV ค่อย ๆ แคบลง — เพราะการกรองบนผลลัพธ์ ไม่ต้องยิง query ใหม่ จึงลองผิดลองถูกได้ไว พอได้เงื่อนไขที่ใช่แล้วค่อยกลับไปใส่ในหน้า selection ให้ถาวร
5

เลือก field ที่จะกรองและที่จะแสดง

ตารางอย่าง ACDOCA มี field เป็นร้อย — ถ้าไม่จัดการ จะทั้งช้าและอ่านไม่รู้เรื่อง

เส้นทาง: Settings → Fields for Selection

  1. เมนู Settings (หรือ Extras ในบางเวอร์ชัน) → Fields for Selection / Field selection
  2. ติ๊กเฉพาะ field ที่ต้องการให้ปรากฏบนหน้าจอ selection
  3. บันทึกไว้ — SE16N จำ setting ต่อ user + ต่อตาราง

เส้นทาง: Change Layout (บนหน้า ALV)

  1. กด Change Layout (ไอคอนตาราง/กริด)
  2. ย้าย field จาก “Column Set” มาที่ “Displayed Columns”
  3. จัดลำดับ · กำหนดความกว้าง · เลือกให้ sort/subtotal
  4. Save layout ตั้งชื่อขึ้นต้นด้วย / เพื่อให้ทีมใช้ร่วมกันได้ (เช่น /TAX_WHT)
Layout ที่ควรสร้างไว้ล่วงหน้า (ทำครั้งเดียว ใช้ทั้งโปรเจกต์)
  • /TAX_ACDOCA — BUKRS · GJAHR · BELNR · DOCLN · RLDNR · RACCT · KTOSL · PRCTR · SEGMENT · RECID · VBUND · SHKZG · HSL · KSL · OSL · BUDAT · BLART
  • /TAX_WITHITEM — BUKRS · GJAHR · BELNR · WITHT · WT_WITHCD · QSREC · WT_ACCO · WT_QSSHH · WT_QBSHH
  • /TAX_CONFIG — สำหรับตาราง ZTAXA_T01 / ZTAXB_T02

ดูชื่อ field ทางเทคนิค vs คำอธิบาย

บนหน้า ALV ให้เปิด Settings → Display → Technical names (หรือติ๊กในหน้า Change Layout) → จะเห็น RACCT แทน “G/L Account” · สำคัญมากเวลาคุยกับ dev เพราะ dev พูดด้วยชื่อทางเทคนิค

ทางลัดที่ทุกคนควรรู้: ถ้าอยู่บนหน้าจอ SAP ใด ๆ แล้วอยากรู้ว่าช่องนั้นคือ field อะไร → คลิกที่ช่อง แล้วกด F1 → Technical Information (ไอคอนค้อน/ประแจ) จะบอก Table name + Field name ให้เอาไปใช้ใน SE16N ได้ทันที
6

จัดการ output — sort · filter · total · subtotal

ลำดับการทำงานที่แนะนำ

  1. Sort ตามคอลัมน์ที่ใช้จัดกลุ่มก่อน (เช่น PRCTR)
  2. Total (Σ) คอลัมน์ตัวเลขที่ต้องการรวม (เช่น HSL)
  3. Subtotal ตามคอลัมน์ที่ sort ไว้ → ได้ยอดรวมต่อกลุ่มทันที

⚠ เรื่องจริงที่เกิดบ่อย: consultant ใหม่เปิด ACDOCA โดยไม่ใส่ filter อะไรเลย แล้วกด Execute · ACDOCA ของบริษัทขนาด Client มีได้ หลายร้อยล้านแถว → query ค้าง · ใช้ memory มหาศาล · กระทบ user คนอื่นทั้งระบบ · basis โทรตาม อย่าให้เป็นคุณ

กติกา 7 ข้อ

  1. ใส่ key field เสมอ — ACDOCA ต้องมีอย่างน้อย RLDNR + RBUKRS/BUKRS + GJAHR
  2. กด “Number of Entries” ก่อน execute — รู้ว่าจะได้กี่แถวก่อนดึงจริง
  3. จำกัดช่วงเวลาให้แคบ — 1 งวดพอ ไม่ต้องทั้งปี ถ้าไม่จำเป็น
  4. ลดคอลัมน์ — Settings → Fields · ยิ่งน้อยยิ่งเร็ว
  5. ถ้าต้องดึงเยอะจริง ๆ ให้รัน background (Program → Execute in background) แล้วดูผลใน SP01
  6. เลี่ยง * นำหน้า — *123 ใช้ index ไม่ได้ ต้อง scan ทั้งตาราง · 123* เร็วกว่ามาก
  7. ถ้าต้องการแค่ยอดรวม ใช้ SE16H — รวมที่ระดับฐานข้อมูล ไม่ต้องดึงแถวมาทั้งหมด

SE16N มีความสามารถแก้ไขข้อมูลตารางโดยตรงผ่าน special command (&SAP_EDIT) ซึ่งในองค์กรที่มี governance ดี จะถูกปิดใน production เสมอ และ การพยายามใช้จะถูกบันทึกไว้และตรวจสอบได้

⚠ จุดยืนที่ถูกต้องของ consultant:
  • • ห้ามแก้ข้อมูลผ่าน SE16N ในทุกระบบ รวมถึง QA/DEV เว้นแต่ได้รับอนุมัติเป็นลายลักษณ์อักษร
  • • การแก้ตารางตรง ๆ ข้ามทุก validation และ business logic → ข้อมูลจะไม่สอดคล้องกัน (เช่น ACDOCA ไม่ตรงกับ BKPF)
  • • ถ้าข้อมูลผิดจริง ให้แก้ผ่าน transaction ที่ถูกต้อง (กลับรายการ + บันทึกใหม่) หรือ ขอ data fix ผ่านกระบวนการ
  • • การที่คุณรู้ว่ามันมีอยู่และเลือกไม่ใช้ คือสิ่งที่ทำให้คุณน่าเชื่อถือ

Auth objectคุมอะไร

11.3 · Confidentiality — สำคัญเป็นพิเศษกับข้อมูลภาษี

  • ข้อมูลใน WITH_ITEM / DFKKBPTAXNUM มี เลขประจำตัวผู้เสียภาษีและชื่อคู่ค้า = ข้อมูลอ่อนไหว
  • ยอดใน ACDOCA คือ ตัวเลขทางการเงินจริงของ client
  • ห้าม screenshot ข้อมูลจริงลง note ส่วนตัว / chat นอกระบบ / study notes
  • ถ้าต้องยกตัวอย่างในเอกสาร ให้ใช้ ข้อมูลสมมติ หรือปิดบังค่าจริง

Self-check

ทวนความเข้าใจ

1. อยากดูข้อมูล 1 ตาราง vs อยากรู้ว่าตารางมี field อะไรบ้าง — ใช้ T-code ต่างกันยังไง?

ดูข้อมูล → SE16N · ดูโครงสร้าง (field, key, index, check table) → SE11 · ถ้าอยากรวมยอด/group by → SE16H · ถ้าต้อง join 2 ตาราง → SQVI

2. * กับ + ต่างกันอย่างไร ยกตัวอย่าง

* = อักขระกี่ตัวก็ได้ (รวม 0 ตัว) · + = อักขระ 1 ตัวพอดี → 3* ได้ 3, 3A, 3AB · 3+ ได้เฉพาะ 3A, 3B … (ยาว 2 ตัว)

3. ค่าอะไรใน ACDOCA ที่บอกว่าบรรทัดนั้นเป็นภาษีหัก ณ ที่จ่าย?

KTOSL = 'WIT' — ใช้เป็นเงื่อนไขหลักของทั้ง TAX-ENH-1 และ TAX-FRM-1

4. จะหาแถวที่ WT_WITHCD “ไม่ว่าง” ต้องทำอย่างไร?

คลิกไอคอนลูกศร → Selection options → เลือก “Not equal to” แล้วปล่อยค่าเป็นช่องว่าง · ไม่ใช่การปล่อยช่องบนหน้าจอว่างไว้ (นั่นแปลว่า “ไม่กรอง field นี้”)

5. ก่อนกด Execute บนตารางใหญ่ ควรทำอะไรก่อน 2 อย่าง?

(1) ล้าง “Maximum no. of hits” หรือกำหนดค่าที่ตั้งใจ · (2) กด “Number of Entries” เพื่อรู้จำนวนแถวจริงก่อนดึง · และต้องแน่ใจว่ามี key field (ledger + company code + ปี) ในเงื่อนไขแล้ว

6. อยากได้ยอดรวมต่อ profit center จาก ACDOCA ทำยังไงใน SE16N?

Sort ตาม PRCTR → เลือกคอลัมน์ยอด (HSL/KSL) กด Total (Σ) → กด Subtotal ตาม PRCTR · จะได้ยอดต่อ profit center ทันที (หรือใช้ SE16H ที่ group by ได้ตรง ๆ)

7. ทำไมการกรองด้วย *123 ถึงช้ากว่า 123*?

เพราะ ดอกจันนำหน้าทำให้ใช้ index ไม่ได้ — ฐานข้อมูลต้อง scan ทุกแถวเพื่อเทียบ ขณะที่ 123* ยังใช้ index หาจากจุดเริ่มต้นได้

8. เจอปัญหา “ยอดในรายงานเบิ้ล 2 เท่า” — ข้อสงสัยแรกคืออะไร?

ไม่ได้กรอง RLDNR (ledger) — เอกสารเดียวกันมีบรรทัดในหลาย ledger (0L leading + T1 tax + อื่น ๆ) · เป็นสาเหตุเดียวกับที่ TAX-FRM-1 ระบุ RLDNR = '0L' ในเส้นทางที่หา PRCTR

9. SE16N แก้ข้อมูลได้ไหม และควรทำไหม?

ในทางเทคนิคทำได้ผ่าน special command แต่ห้ามทำ — production ปิดไว้ · การใช้ถูก log และ audit · การแก้ตารางตรงข้ามทุก validation ทำให้ข้อมูลไม่สอดคล้องกัน · ถ้าข้อมูลผิด ให้แก้ผ่าน transaction ที่ถูกต้อง

10. ก่อนบอก user ว่า “ไม่มีข้อมูล” ต้องเช็คอะไรเป็นข้อสุดท้าย?

ระบบและ client ที่คุณกำลังดูอยู่ (DEV / QA / PRD · client number) — ดูมุมขวาล่างของหน้าจอ SAP · และควรพูดชื่อระบบทุกครั้งที่รายงานผล
