FUT loop (6 ขั้น)

  1. อ่าน FD ทีละ section → ลิสต์ กฎที่เทสได้ (selection, ทุก step ของคอลัมน์, filters, errors)
  2. สร้าง specimen: หนึ่งเอกสารต่อหนึ่งกฎ · ใช้ discriminating pairs (สองใบต่างกันตัวแปรเดียว)
  3. คำนวณ expected ไว้ก่อนรัน (TCURR rates, Σ lines)
  4. รัน · capture selection screen + output · trace ใน SE16N (BKPF, BSEG, BSET, WITH_ITEM, ACDOCA 0L, BSAK, TCURR)
  5. Pass → evidence · Fail → จัดชั้น (master data / config / posting / report logic) ด้วย three-layer model → เปิด defect
  6. Retest หลัง fix · regression sister outputs (shared engine ZTAXB_R01)

Three-layer check
  1. Master data มีไหม — CEPC, SKA1 …
  2. Authorized ให้ CoCd ไหม — CEPC_BUKRS, SKB1, T8JJ
  3. Post จริงเป็นอะไร — ACDOCA / BSEG

หายที่ชั้น 3 = posting / config · มีที่ชั้น 3 แต่ไม่ออก output = report / filter

Working principles

  • Evidence before action — SE16N / FB03 / config · ความมั่นใจ >95% ก่อน escalate · retract ทันที เมื่อหลักฐานขัด
  • One document per ticket · หนึ่ง root cause ต่อ ticket — ไม่ bundle
  • อ่านค่าที่ post แล้ว ห้ามคำนวณภาษีใหม่ตอน runtime · ใช้ key เต็มทุก ACDOCA read
  • Fix ใน layout / path หนึ่งมักกลับมาที่อื่น — regression sibling (input/output, standard/cash call, report/attachment/text)
  • อธิบาย ABAP เป็นกฎ IF/ELSEIF ก่อนเขียนโค้ด · ห้ามใช้ sy-tcode ระบุโปรแกรมใน background job (ใช้ ABAP memory ID) · BINARY SEARCH ต้อง sort · DELETE ต้องมี key เต็มรวม GJAHR/BUKRS
  • “ไม่มีใครค้านใน review” ≠ อนุมัติ — อ้าง approval เมื่อมี written trail เท่านั้น
  • Evidence package ให้ stakeholder: what we found / what it means / what we need

Components: Functional / FI / Tax
1. Description — scenario + the one document
2. Current Result — what the report shows (values)
3. Reproduce Steps — T-code, variant, selection
4. Expected Results — per FD step, with numbers
5. Proposed Fix — minimal, at the step / form level
6. Objects Modified

Self-check

1. FUT ต่างจาก SIT อย่างไร?

ดูเฉลย
FUT = object เดียวเทียบ FD (DEV 120) · SIT = E2E scenario ข้ามโมดูลใน QAS โดยแต่ละ step มี team owner

2. ก่อนรัน FUT ต้องมีอะไรนอกจาก specimen?

ดูเฉลย
Expected values ที่คำนวณไว้ก่อน (TCURR, Σ lines) และ baseline / selection screen capture

3. Defect ที่ดีหนึ่งใบควรมีกี่เอกสาร?

ดูเฉลย
หนึ่งเอกสาร หนึ่ง root cause — ไม่ bundle
