TAX-FRM-2 — WHT Certificate Form
พิมพ์หนังสือรับรองหัก ณ ที่จ่าย ยื่นกรมสรรพากรเมียนมา (IRD) · แบบ IRD(IT)-05-01

Smart Form · ZTAXA_F01_MM3 Type · Form (Retrofit) Process · 01.01.07.03 WHT Priority · P1 · Medium
Source: FD TAX-FRM-2 v1.0 (10/09/2025) · Business Owner: Client Tax team · Geography: Myanmar · ชื่อผู้ review ในเอกสารต้นฉบับถูกตัดออกเพื่อความเป็นส่วนตัว

หนึ่งใน 3 object หลักที่คุณดูแล (คู่กับ RPT-2 / RPT-1). object นี้เป็น Form (Smart Form) ไม่ใช่ report — หน้าที่คือ generate + print หนังสือรับรอง WHT ตามฟอร์มทางการของเมียนมา IRD(IT)-05-01 (ออกตาม Section 16(b) ของ Income Tax Law). แก่นที่ต้องเข้าใจ = เลือกสกุลเงินพิมพ์ (MMK / USD / doc) และ logic ใส่อัตรา DTA ในช่อง Remark

Key Takeaways — TAX-FRM-2
  • เป็น Form (Smart Form ZTAXA_F01_MM3) ไม่ใช่ report — พิมพ์ใบรับรอง WHT ยื่น IRD เมียนมา (แบบ IRD(IT)-05-01)
  • สกุลเงินที่พิมพ์ขึ้นกับ สกุลที่จ่าย: จ่าย MMK → พิมพ์ MMK · จ่ายไม่ใช่ MMK/USD → พิมพ์ USD · หรือเลือกพิมพ์ document currency (เช่น THB)
  • Selection: ลบ radio LC1/LC2/LC3 เดิม · เพิ่ม radio “LC1/LC2 Currency” และ “Document Currency”
  • ยอดเงินดึงจาก WITH_ITEM — 3 ชุด field ตามสกุล: MMK=WT_QSSHH/QBSHH · USD=WT_QSSH2/QBSH2 · doc=WT_QSSHB/QBSHB
  • ช่อง Remark ใส่อัตรา DTA (จาก tax code D1..H4) + ชื่อประเทศ vendor (BSAK→LFA1→T005T)
  • Dependency: ต้องมี TAX-RPT-8 (MM WHT Report) เพื่อรัน · volume ~80–100/เดือน
Scope ยังไม่ยืนยัน (D6): ต้องยืนยันกับ project lead ก่อนลงแรงต่อ · คอร์ส TAX-406 WHT-MM สอนแล้ว 8-Jul-2026 คู่กับ RPT-8 · MM WHT types B0 resident / B2 non-resident หักตอนจ่าย
สิ่งที่ต้องเคลียร์ก่อนเทส (FUT notes, 7-Sep):
  • FD ขัดกันเองเรื่องสกุลที่ไม่ใช่ MMK/USD — พิมพ์เป็น USD หรือ raise error TBC กับ MM tax team
  • สำหรับ WHT ที่หักตอน invoice: BKPF ของเอกสารไหน (payment หรือ invoice) เป็นตัวตัดสินสกุล — ยังไม่ชัด
  • Comment “TAX-FRM-2” ในโค้ด ZTAXA_R01 อยู่ข้าง logic PC/RI ของไทย — น่าจะ label ผิด (ควรเป็น FRM-1) ต้องยืนยัน ownership
  • Checkbox “Signature Not Required” + การ maintain ZTAXA_T09 · MM company code และ specimens ยังไม่ได้ระบุ

วัตถุประสงค์ + การเลือกสกุลเงินพิมพ์

ต้องพิมพ์ใบรับรองได้ทั้ง MMK และ USD — สกุลขึ้นกับ “สกุลที่จ่าย (payment currency)”

สกุลที่พิมพ์บนใบรับรอง

Rule 1
จ่ายเป็น MMK
payment currency = MMK → พิมพ์ใบรับรองเป็น MMK
Rule 2
จ่ายไม่ใช่ MMK / USD
payment currency ≠ MMK และ ≠ USD → พิมพ์เป็น USD (global currency)
Rule 3
Document Currency
กรณีต้องพิมพ์ตาม สกุลเอกสารจริง (เช่น THB) → เลือก radio “Document Currency”
จำง่าย ๆ: จ่าย MMK → MMK · อย่างอื่น → USD · ยกเว้นสั่งพิมพ์ตามสกุลเอกสาร (THB ฯลฯ) ด้วย radio “Document Currency”

ยอดเงินดึงจากไหน (WITH_ITEM 3 ชุด)

field ยอดเงิน ([14] ยอดจ่าย · [15] ยอด WHT · [16]/[17] รวม) ทั้งหมดมาจาก WITH_ITEM โดยส่งคีย์ BUKRS + GJAHR + WHT code ≠ blank แล้วเลือก field ตามสกุล:

โหมด (radio)เงื่อนไขยอดจ่าย [14/16]ยอด WHT [15/17]
LC1/LC2 · MMKBKPF-WAERS = MMKWT_QSSHHWT_QBSHH
LC1/LC2 · USDBKPF-WAERS ≠ MMKWT_QSSH2WT_QBSH2
Document Currencyเลือก radio docWT_QSSHBWT_QBSHB
เกร็ด suffix ของ WITH_ITEM: ...HH = local currency 1 (MMK) · ...H2 = local currency 2 (USD) · ...HB = document currency · [18] Total in Letter = ยอดรวมเป็นตัวอักษร

Logic Changes (3 ข้อ)

อ่าน 3 ข้อนี้ครบ = เข้าใจหัวใจของ object นี้

Logic 1 — radio “LC1/LC2 Currency”

ส่งคีย์ WITH_ITEM = company code (BUKRS) + fiscal year (GJAHR) + WHT code ≠ blank แล้วเลือก field ตามสกุลของ BKPF-WAERS:

  • ถ้า MMK (BKPF-WAERS = MMK): [14]=WT_QSSHH · [15]=WT_QBSHH · [16]=SUM(QSSHH) · [17]=SUM(QBSHH) · [18]=amount in words
  • ถ้า ≠ MMK: [14]=WT_QSSH2 · [15]=WT_QBSH2 · [16]=SUM(QSSH2) · [17]=SUM(QBSH2) · [18]=amount in words

Logic 2 — radio “Document Currency”

คีย์เดียวกัน แต่ใช้ field สกุลเอกสาร: [14]=WT_QSSHB · [15]=WT_QBSHB · [16]=SUM(QSSHB) · [17]=SUM(QBSHB) · [18]=amount in words

Logic 3 — อัตรา DTA ในช่อง Remark

อ่าน WITH_ITEM-WT_WITHCD (ตาม BUKRS + GJAHR) ถ้าเป็น DTA code ให้พิมพ์อัตราในช่อง Remark แล้ว concatenate กับชื่อประเทศ vendor · ถ้าไม่ใช่ code เหล่านี้ = ปล่อยว่าง
