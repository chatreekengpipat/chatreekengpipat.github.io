TAX-RPT-4 — Current Tax Report ต่างประเทศ (ZTAXB_R02)

Type · Report Nature · New T-code · ZTAXB_R02 Output · FIORI custom report Complexity · Complex Priority · P1 Geo · Overseas (12+ ประเทศ)

Key Takeaways — 8 ข้อ
  • Standard layout 3 ต้น — CIT_Standard · PITA_Standard · PSC_Standard · ประเทศต่าง ๆ = standard + overlay
  • ยกเว้น 2 ตัวที่ไม่ใช้ standard layout เลย — PSC_MY และ MTJDA_MY
  • ZTAXB_T02 คือตารางใหม่ที่รวม “ความต่างรายประเทศ” ไว้ทั้งหมด (GL mapping + % + capped + profit center + validity)
  • บริษัทเดียวกัน layout เดียวกัน ยัง map GL คนละชุดได้ (เช่น PSC_OM ของ OM01 กับ OM02)
  • ยืมตารางของ RPT-3 6 ตัว โดยเพิ่ม flag “Overseas” ใน ZTAXA_T05/ZTAXA_T06
  • Manual adjustment ของต่างประเทศใช้ prefix OS_* เพื่อแยกจากของไทยในตารางเดียวกัน
  • TAX_INFO = field แก้ปัญหา “บริษัท/PC/segment เดียวกันแต่คนละประเทศ”
  • ปลายทางเหมือนกันหมด: ACL3 → ACL4 (tax rate) → ACL5 → ACL · ขาดทุนเก็บลง LCF

“GL movement” — C/F − B/F

GL movement = ยอดยกไป (carried forward) − ยอดยกมา (brought forward) = การเคลื่อนไหวของบัญชีงบดุลในงวด ใช้กับ item type ที่มาจาก บัญชีงบดุล ไม่ใช่บัญชีกำไรขาดทุน เช่น - ROU: UNREALIZED FX GAIN/LOSS (REVAL) → ไม่กลับเครื่องหมาย - DECOM LIAB: UNREALIZED FX GAIN/LOSS → ไม่กลับเครื่องหมาย - DECOM FUND - ACTUAL PAID → (deductible) - INTANGIBLE DRILLING COSTS: PER TAX → (deductible)
ทำไมบัญชีงบดุลต้องใช้ movement: บัญชี P&L ยอดในงวด = การเคลื่อนไหวอยู่แล้ว แต่บัญชีงบดุลเก็บ ยอดสะสม — ถ้าเอายอดคงเหลือมาใส่รายงานภาษี จะได้ยอดสะสมทั้งชีวิตของบัญชี ไม่ใช่ของงวดนี้ → นี่คือเหตุผลที่ item type เดียวกันอาจถูกระบุเป็น “GL” ในที่หนึ่ง แต่ “GL with condition” ในอีกที่

Expert notes

1) design pattern ที่ควรจดจำ — “config over code”

ความต่างของ 12+ ประเทศ ถูกผลักลงไปอยู่ใน ตาราง เกือบทั้งหมด (mapping · % · capped · profit center · validity) สิ่งที่เหลือในโค้ดคือ โครง node chain และ สูตรพิเศษไม่กี่ตัว (deemed sales, Malaysia ACL9/13/14) → ผลคือ เพิ่มประเทศใหม่โดยไม่ต้องแก้โปรแกรม ตราบใดที่กฎหมายเข้าโครงเดิมได้ นี่คือคำตอบที่ดีมากเมื่อถูกถามว่า “ทำไมออกแบบแบบนี้”

2) จุดที่ design นี้ “แตก” — และ FD ก็ยอมรับ

PSC_MY และ MTJDA_MY ไม่ใช้ standard layout เพราะกฎหมายมาเลเซีย มีโครงการหักขาดทุน 2 ชั้น (capital allowance → business loss) ที่ยัดเข้าโครง permanent/temporary ไม่ได้ → บทเรียน: pattern ที่ดีไม่ได้แปลว่าครอบคลุม 100% · การยอมรับข้อยกเว้นแต่เนิ่น ๆ ดีกว่าฝืนบิด standard

Self-check

ทวนความเข้าใจ

1. Standard layout มีกี่ต้น และมี layout ไหนที่ไม่ใช้ standard เลย?

3 ต้น — CIT_Standard · PITA_Standard · PSC_Standard · layout ที่ ไม่ใช้ standard คือ PSC_MY และ MTJDA_MY

2. บริษัท OM01 และ OM02 ใช้ layout PSC_OM เหมือนกัน แต่ผลลัพธ์ต่างกันได้อย่างไร?

เพราะ ZTAXB_T02 มีคอลัมน์ Com code → map GL คนละชุดได้ (OM01 ใช้ GL1xxx · OM02 ใช้ GL2xxx) และยังมี item type ที่ใช้ได้เฉพาะบางบริษัท — เช่น SALE PER TAX – GL เฉพาะ OM01 · SALE PER TAX – TAX CR REPORT เฉพาะ OM02

3. TAX_INFO ใช้แก้ปัญหาอะไร ยกตัวอย่าง

แก้กรณีที่ company code + profit center + segment เหมือนกัน แต่ต้องคำนวณตามกฎ 2 ประเทศ เช่น MTJDA_MY (มาเลเซีย) vs MTJDA_TH (ไทย) หรือ CIT_THMM — ระบบจะใช้ TAX_INFO เลือก tax rate จาก ZTAXA_T02 และแยก LCF ใน TAX-RPT-5 ไม่ให้ปนกัน

4. เขียนสูตร ACL3 และ ACL

ACL3 = ACL1 + ACL2 + OS_AU1 (taxable income/loss ก่อน LCF + LCF + manual adj LCF) · ACL = ACL5 − ACL6 − OS_AU2 (ภาษี YTD เดือนนี้ − YTD เดือนก่อน − true-up = ภาษีของเดือนนี้ MTD)

5. ถ้า TAXABLE INCOME AFTER LCF เป็นยอดเดบิต ACL5 เท่ากับเท่าไร?

เท่ากับ 0 — เพราะเดบิต = ขาดทุน จึงไม่มีภาษี · และโปรแกรมต้อง เก็บผลขาดทุนลง ZTAXB_T01 เพื่อยกไปใช้ปีหน้า · ถ้าเป็นเครดิต (กำไร) → ACL5 = ACL3 × ACL4 กลับเครื่องหมาย

6. A212* ใน GL mapping แปลว่าอะไร?

แปลว่าบัญชี A2120000 ถึง A2129999 — ใช้ดอกจันแทนการพิมพ์ช่วง (เช่นเดียวกับ A1* = A100000–A199999) ใช้คู่กับคอลัมน์ Exclude GL เพื่อตัดบัญชีบางตัวออกจากช่วงได้

7. Deemed sales ของ PSC_DZ ต่างจาก PSC_OM ตรงไหน?

PSC_DZ ต้องเช็ค LCF และเทียบ EBT ก่อน 2 ขั้น — ถ้ามี LCF หรือขาดทุน → deemed sale = 0 · ส่วน PSC_OM คำนวณตรง ๆ ไม่มีขั้นเช็ค LCF · นอกจากนี้ฐานการคำนวณต่างกัน (DZ ใช้ Manual Adj SALE PER TAX · OM ใช้ Sale per tax + Cost recovered − Utilised) ทั้งคู่ปิดท้ายด้วยการหัก GL A410X031 ของเดือนก่อน

8. มาเลเซียมีการหักขาดทุนกี่ชั้น อะไรบ้าง?

2 ชั้น — ชั้นที่ 1 Unabsorbed capital allowances (ACL8→ACL10 · หักด้วย ACL9) ชั้นที่ 2 Unabsorbed business loss (ACL12→ACL15 · หักด้วย ACL14) ปิดท้ายที่ ACL16 Assessable (Income)/Loss = ACL11 + OS_PU25 − ACL14 · และ C/F ทั้ง 4 ประเภท (marginal / non-marginal / investment / non-investment) โอนข้ามประเภทไม่ได้
