Key Takeaways — จำ 6 ข้อนี้พอ
  • ตัวชี้ขาดว่าบรรทัดไหนคือ WHT = ค่าคงที่ข้อความ WIT (Withholding tax transaction line-item identifier)
  • WHT Type บอกว่าเป็น “ภาษีอะไร” → Recipient Type ยืนยัน “ยื่นแบบไหน” → WHT Code ระบุ “ประเภทเงินได้ในช่อง 5”
  • DMEEX 6 ต้น = 6 แบบยื่น · ใช้ EXIT ร่วมกัน 2 ตัวสำหรับ ฐานภาษี และ ภาษีหัก
  • Delta S/4 = Profit Center (validate CEPC-PRCTR) + Recovery Indicator (validate T8JJ-RECID คู่กับ BUKRS)
  • ไม่ว่าจะเลือกอะไร ไฟล์ยังแยกตาม Business Place (สาขา) เสมอ — เพราะ RD ยื่นเป็นรายสาขา
  • เอกสารกลับรายการ (reversal) ต้องไม่ออกไฟล์ — นี่คือ TC-007 และเป็นบั๊กคลาสสิกของงานตระกูลนี้

Logic delta — 1 การรัน แตกเป็นกี่ไฟล์

ส่วนเดียวที่เป็น “ตรรกะใหม่” จริง ๆ ในเอกสารฉบับนี้

  1. ถ้าเลือก Profit Center — ให้ generate text file แยกตาม profit center ที่เลือก
  2. ถ้าเลือก Recovery Indicator — ให้ generate text file แยกตาม recovery indicator
  3. ทุกกรณี ไฟล์ยังคงถูกแยกตาม Business Place (สาขา) — ข้อนี้เป็นพฤติกรรมพื้นฐาน ไม่ใช่ทางเลือก
สูตรจำนวนไฟล์ (mental model)

จำนวนไฟล์ ≈ (แบบยื่นที่มีข้อมูล) × (Business Place) × (Profit Center ที่เลือก | Recovery Indicator ที่เลือก)

→ ถ้าไม่เลือกทั้ง PC และ RECID ก็เหลือแค่ (แบบยื่น × สาขา) เหมือน ECC เดิม → นี่คือเหตุผลที่ volume ระบุไว้ว่า >1,000 records/เดือน แต่จำนวน “ไฟล์” อาจสูงกว่าที่คนคาดมาก

⚠ TC-004 คือ test ที่คนมักคิดไม่ถึง: เลือก Profit Center และ Recovery Indicator พร้อมกัน FD ระบุว่าต้องออกไฟล์ได้ตามทั้งสองเงื่อนไขพร้อมกัน — ไม่ใช่ “อันใดอันหนึ่ง” ตอนเทสต์ให้เตรียมข้อมูลที่ profit center หนึ่งมีหลาย recovery indicator เพื่อดูว่าโปรแกรมแตกไฟล์ถูกจริง

Self-check

ทวนความเข้าใจ

ตอบในใจก่อนกดดูเฉลย

1. ธุรกรรมหนึ่งมี WHT Type = 4C แต่ Recipient Type = 03 จะออกในไฟล์ไหน?

ไม่ควรออกที่ไหนเลย และนี่คือ master data ผิด — 4C อยู่ในกลุ่ม ภ.ง.ด.53 (นิติบุคคล) แต่ 03 คือ recipient type ของ ภ.ง.ด.3 (บุคคลธรรมดา) เงื่อนไขทั้งสองต้องสอดคล้องกัน รายการนี้จะหลุดจากทั้งสองไฟล์แบบเงียบ ๆ → ต้องแก้ที่ vendor master / WHT type ของเอกสาร ไม่ใช่แก้โปรแกรม

2. Recovery Indicator validate จากตารางอะไร และทำไมต้องส่ง company code ไปด้วย?

จาก T8JJ-RECID (ตาราง JVA) และต้องส่งคู่กับ BUKRS เพราะ recovery indicator เป็นค่าที่นิยามภายใต้บริบทของ joint venture ในแต่ละ company code — validate ลอย ๆ จะยอมรับค่าที่ใช้ไม่ได้จริง แล้วได้ไฟล์เปล่าโดยไม่มี error

3. ทำไม ภ.ง.ด. 1ก ต้องพึ่ง enhancement ZTAXA_E01 ในขณะที่แบบอื่นไม่ต้อง?

เพราะ 1ก เป็น ใบสรุปทั้งปีต่อผู้มีเงินได้ 1 คน = 1 บรรทัด (field 13 = “Total amount paid per year”) ในขณะที่ WITH_ITEM เก็บเป็นรายเอกสาร → ต้อง sum ตาม partner ก่อน DMEEX จะ map นอกจากนี้ enhancement ยัง sort ตาม company code → partner → WHT code ให้ด้วย

4. ถ้าเลือก Profit Center แล้ว ไฟล์จะยังแยกตามสาขาอยู่ไหม?

ยังแยก — FD ระบุชัดว่า “files separated by business place” เป็นพฤติกรรมพื้นฐาน ส่วน PC / RECID เป็น มิติเพิ่ม ไม่ใช่มิติแทนที่ ดังนั้นเลือก PC = ยิ่งได้ไฟล์เยอะขึ้น ไม่ใช่น้อยลง

5. EXIT 2 ตัวชื่ออะไร และทำหน้าที่ต่างกันอย่างไร?

ZDMEE_EXIT_WHT_BASE = คำนวณ ฐานภาษี (WHT base) · ZDMEE_EXIT_WHT_AMT = คำนวณ ยอดภาษีที่หัก (WHT amount) ทั้งคู่ถูกเรียกจาก DMEEX tree ทุกต้น (ทั้ง PND3 และ PND53 ระบุไว้ตรง ๆ ใน FD)

6. Object นี้ครอบคลุม ภ.ง.ด. 54 หรือไม่?

ไม่ — ENH-1 มีแค่ 1, 1ก, 2, 2ก, 3, 53 · ภ.ง.ด. 54 (จ่ายไปต่างประเทศ) อยู่ใน TAX-FRM-1 (ใบแนบ) และ TAX-RPT-1 (กระทบยอดกับ ภ.พ.36)
