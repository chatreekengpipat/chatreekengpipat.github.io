TAX-RPT-2 — Oman VAT Report
“OMAN Tax Report – Cash Call Included” · สอง data path ในโปรแกรมเดียว

Program · ZTAXA_R04 (copy of RFUMSV00) CoCd · OM01 OM · OMR 3 dp L4 · 01.01.07.02 Indirect Status · FUT exit → SIT

Source: FSD TAX-RPT-2 v1.0 · FUT notes (content v2, 7-Sep) · knowledge base 20-role-wricef-owner §2 (16-Oct) · ABAP = RPT-2 developer (SI)

รายงาน VAT ของ Oman ที่ต้อง “เห็น” ธุรกรรม JVA cash call ด้วย — แต่ cash call ไม่มีบรรทัดภาษีใน BSET (tax code I0 = 0%) โปรแกรมจึงมี สองทางเดิน: ทางปกติอ่าน BSET · ทาง cash call อ่าน BSEG บรรทัด vendor · กุญแจของ object นี้คือ ทุกครั้งที่อ่าน defect ให้ถามก่อนว่าเป็น path ไหน — แก้ path เดียวแล้วอีก path จะกลับมาพังเสมอ
Overview Two data paths JVA lookup ดึงจากตารางไหน ECC → S/4 Run step-by-step FUT evidence Defects & decisions Tests Self-check
Key takeaways
  • ถาม path ไหน ก่อนอ่าน defect: standard (BSET) vs cash call (BSEG vendor line)
  • อ่านค่าที่ post แล้ว ห้ามคำนวณภาษีใหม่ — สูตร 5% ตอน runtime เคยสร้างภาษีผีและเศษปัดเพี้ยน (Bug 1)
  • attribute JVA ทุกตัวต้องมาจาก ACDOCA แถวเดียวกันที่ match · lookup ต้องมี BUKRS + BELNR + GJAHR + RLDNR '0L' — profit center ไม่เคย unique (Bug 2)
  • Report only ไม่ post · venture filter มีผลเมื่อติ๊ก “Activate JVA Splitting” เท่านั้น
  • เปิดอยู่: Total/Balance ของเอกสาร multi-PC (root cause เดียวกับ TAX-RPT-6) · cash call ไม่เข้า “Balance of all company codes”

JVA lookup — three layers (finalised)

  1. Tax row: KTOSL ใน MWS / VST / ESA / ESE / NVV + MWSKZ ตรง + venture PC ตรง — ห้ามใช้ “KTOSL ไม่ว่าง” เพราะจะติด special GL key เช่น AGD
  2. Fallback base row: PRCTR + MWSKZ, KTOSL ว่าง, ตัด LINETYPE 02* / 03*
  3. Cash-call direct link: ACDOCA-DOCLN = BSEG-BUZEI
กฎเหล็ก: copy VNAME, EGRUP, RECID, PRCTR, KSL จาก แถวเดียวกัน ที่ match · ทุก read ต้องมี key เต็ม BUKRS + BELNR + GJAHR, RLDNR = '0L'

Selection screen

  • ช่องมาตรฐานของ RFUMSV00 + Oman country, native currency option, JVA split, joint venture, equity group, recovery indicator
  • Further selections: Profit Center (validate CEPC) · Recovery Indicator (validate T8JJ)
  • Venture / equity range มีผลเฉพาะเมื่อติ๊ก Activate JVA Splitting · บรรทัด cash call ไม่สนใจ venture filter เลย
Safety: ห้ามติ๊ก Update run ตอนเทส · SE16N แสดง OMR โดยไม่ shift 3 ทศนิยม — “1,000.00” ใน SE16N = 100.000 OMR · อย่าอ่าน screenshot ผิด

Run step-by-step

  1. ธุรกรรมภาษีในงวดถูก post — รวม JVA cash call (JD/JK, A213X025, I0) · VIM จับ tax invoice + scan date
  2. รัน ZTAXA_R04 → Company Code OM01 + งวด
  3. Further Selections → Profit Center และ/หรือ Recovery Indicator · ติ๊ก Activate JVA Splitting ถ้าจะกรอง venture
  4. เลือก Output / Input tax → Execute (ไม่ติ๊ก Update run)
  5. ตรวจ line items, Balance per company code, Balance of all company codes · export
  6. กระทบกับ GL ภาษี (A149X017 / A212X020) → ใช้เป็นฐาน Oman VAT return

Cash call ที่เทสจริงมี RI 2 ค่า: บรรทัด customer = NN · บรรทัด revenue = CP · segment CIT_OM — ตรวจทั้งคู่
