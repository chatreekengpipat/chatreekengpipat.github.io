  • Sign fix เสร็จแล้ว: abs(FC) × sign(RC)

TAX-RPT-1 — multi-PC / RI = split lines (3-Sep, TKT-01) AGREED

  • 1 แถวรายงานต่อ 1 ACDOCA WIT line (HSL ≠ 0, ข้ามบรรทัดศูนย์) — ไม่ใช่ต่อ comma
  • WHT amount ต่อแถว = HSL ของ WIT line นั้น (ไม่ prorate)

  • ยังเปิด: คอลัมน์ VAT36 บนแถว split · partial payment → รอ team lead (D2)

DRC statutory forms — ไม่ใช้ (Cadence 23-Jul-2026) AGREED

  • CR-A dropped — DRC statutory forms จะไม่ถูกใช้ · DRC ใช้สร้าง PP30 text file เท่านั้น (UTC ยืนยันแล้ว)
  • แบบ / ใบแนบมาจาก WRICEF: FRM-4 · FRM-1 · FRM-3 · FRM-6 · RPT-6 — อย่า raise ว่า DRC form ไม่ออก · ดู DRC vs WRICEF map

TAX-RPT-2 — by design

  • เป็น report อย่างเดียว ไม่ post · tab “Tax payable posting” ที่ติดมาจาก RFUMSV00 — ซ่อนหรือทำ negative test ยังรอ (D5)
  • Venture / equity filter มีผลเฉพาะเมื่อติ๊ก “Activate JVA Splitting”
  • รันแล้วว่างเพราะ placeholder SEL_VN / SEL ค้างในช่อง = test-setup error ไม่ใช่ defect

SIT — expected ไม่ใช่ defect

  • เอกสาร stock: LC2 rate มาจาก material valuation (rate ต่อบรรทัดต่างกันได้)
  • เอกสารไทยที่ไม่มี tax code แต่มี business place default ของ CoCd
  • NVV codes ไม่มีบรรทัดภาษีแยก (ภาษีรวมในบรรทัด cost)
  • WHT amount = 0 บน invoice สำหรับ type ที่หักตอนจ่าย (MY / MM)
  • LC3 ว่างสำหรับ company code MY / MM

Lessons learned — อย่าทำซ้ำ

  1. แบบ PND54 ไม่ได้มาจาก SAP DRC — TAX-FRM-5 ถูกยกเลิก · มาจาก FRM-3 output group AP1 Print form 2 แม้ Blueprint ยังเขียนว่า DRC
  2. พูดว่า output group ไม่ใช่ “output code”
  3. RPT-7 รันบนแอป Generic WHT Reporting มาตรฐานตาม FD — อย่าสรุปว่าเป็น ZTAXB_R01
  4. “BEPS คำนวณจาก CIT” ผิด — CIT/PITA เป็น covered taxes · ฐานคือ accounting profit
  5. วงเล็บในชื่อคอร์ส “(BEPS&PITA)” = กลุ่มผู้เข้าอบรม — อย่าเถียงชื่อจาก scope WRICEF
  6. ระวังชื่อเล่นคนซ้ำ/คล้ายกันในทีม client — ยืนยันตัวคนก่อนส่งงาน
  7. ก่อนประกาศ defect ให้เช็ก config และ selection screen (CoCd ผิด Client-Intl vs MY01 · placeholder “SEL_VN” · value-help pop-up บังปุ่ม Go)
  8. Caption ของ screenshot ต้องตรงกับสิ่งที่ภาพพิสูจน์ (ใส่ PC แล้ว · กด Go แล้ว · CoCd ถูก · form ถูก เช่น BC/A5 = CP37A ไม่ใช่ CP37)
  9. กับฝั่ง client อย่าเสนอวันที่เอง และอย่าขอให้เขา “ช่วยเช็กงานเรา”
  10. FD ขึ้นหน้าใหม่ซ่อนเงื่อนไขได้ — เคยสรุปว่า RPT-1 step 33 “ไม่มี KTOSL” ผิด (เงื่อนไขอยู่หน้าถัดไป) และถอนคำพูดแล้ว
  11. เคยเดาเกินหลักฐาน: ค่าความมั่นใจของ 5A, root cause “FC = 0” ก่อนเวลา, ใช้ CPUDT เป็นวันอ้างอิง WHT — เช็ก config และเอกสารก่อนเสมอ
  12. Same-day vs backdated · Sunday fallback: TCURR “−1” ที่ตกวันหยุดจะถอยไปศุกร์ — doc 552 ดูถูกเพราะบังเอิญ
  13. แก้ RPT-2 path เดียวโดยไม่แก้อีก path — กลับมาเป็น defect เสมอ
  14. ห้ามใช้คำว่า “T-1” กับ GL team เรื่อง TKT-02 — acceptance คือ “bank line uses the payment doc’s date”

Self-check

1. RPT-1 แถวที่จ่ายเป็น FC แสดง VAT36 base ≠ WT base — เปิด defect ได้ไหม?

ดูเฉลย
ไม่ได้ — by design ตาม step 28 final (3-Sep): VAT36 ใช้สกุล invoice × TCURR M @ T-1 ส่วน WHT ใช้มูลค่าจ่ายจริง · เช็กว่า FC เท่ากันก่อนตีความส่วนต่าง THB

2. Payment มี 2 PC — รายงาน RPT-1 ต้องออกกี่แถว และ WHT amount ต่อแถวมาจากไหน?

ดูเฉลย
1 แถวต่อ ACDOCA WIT line (HSL ≠ 0) · WHT = HSL ของบรรทัดนั้น · base prorate ตาม ratio โดยบรรทัดสุดท้ายรับเศษ

3. RPT-2 รันแล้วว่างทั้งที่มีข้อมูล และช่อง venture ยังเป็น “SEL_VN” — เป็น defect ไหม?

ดูเฉลย
ไม่ — test-setup error (placeholder ค้าง) · venture filter มีผลเฉพาะเมื่อติ๊ก Activate JVA Splitting

4. แบบ PND54 ออกจากระบบไหน?

ดูเฉลย
ไม่ใช่ DRC (FRM-5 ยกเลิก) — ออกจาก FRM-3 output group AP1 บน Generic WHT Reporting

5. เอกสาร MY มี WHT amount = 0 บน invoice และ LC3 ว่าง — ผ่านไหม?

ดูเฉลย
ผ่าน — MY หักตอนจ่าย (amount 0 ที่ invoice) และ LC3 มีเฉพาะ CoCd ไทย
