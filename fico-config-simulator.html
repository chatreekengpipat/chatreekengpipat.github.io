FI/CO Configuration Simulator

Most portfolios describe configuration. This one lets you do it. Pick a transaction event — a goods receipt, a vendor invoice, a customer billing — then set the config a functional consultant actually maintains: the tax code, the valuation class that steers account determination, the reconciliation account group. The balanced FI document rebuilds live, and every posting line is traced back to the config object (T007, OBYC, VKOA, the recon account) that produced it. It's the same logic I reason through when I configure and test SAP FI: change one setting, and see exactly which line of the journal entry moves.

T007A · FTXP
Tax code

The tax code carries the rate and the tax G/L account. Change V1 → V0 on a vendor invoice and the input-VAT line simply disappears — the rest of the document stands. That's why tax config is maintained once, centrally, not coded per posting.

OBYC · MM → FI
Automatic account determination

On a goods receipt, SAP reads posting key BSX for the material's valuation class to pick the inventory account, and WRX for GR/IR clearing. Switch the valuation class and the debit account changes — no manual G/L entry, ever.

VKOA · SD → FI
Revenue account determination

Billing resolves the revenue account from account key ERL so sales post to the right P&L line automatically, while output VAT posts to its own tax account. Configuration, not a hand-picked account, decides where revenue lands.

Recon account · account group
Sub-ledger → G/L link

The vendor's or customer's account group fixes the reconciliation account — the single G/L account that mirrors every sub-ledger posting. It's how AP and AR stay tied to the general ledger without a manual reconciliation step.
